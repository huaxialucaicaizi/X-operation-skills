# 热点联动

每天从当日 AI 热点里挑能讲增长打法的，给热点加上获客/激活/留存/变现/扩张的视角，用于当日选题和互动。热点只是入口，增长打法才是内容。

## 热点从哪来

热点来源在本地配置中设定，见 [../templates/growth-config.example.md](../templates/growth-config.example.md) 的「热点来源」。本仓库不写死任何账号、榜单或服务。

- 只用作者在配置中列出、且当前能正常访问的来源。
- 不用付费 X API，不购买数据服务，不取 Cookie，不绕过登录或限制。
- 每条热点记录：来源、链接、看到的时间。

## 筛选：先过增长门槛

热点和普通选题用同一道门槛，见 [../../growth-topics/references/topic-gates.md](../../growth-topics/references/topic-gates.md)。纯新闻、纯融资、纯模型跑分，落不到增长动作的不选。

能讲的热点通常有这些特征：

- 涉及一个具体产品的发布、定价、渠道、功能或用户变化
- 能写出「谁，对哪类用户，做了什么」
- 有公开、可核的事实；没有就不写结论

## 加增长视角

| 环节 | 可以问的问题 |
|---|---|
| 获客 | 新用户从哪个入口来？靠什么传播？ |
| 激活 | 用户第一次体验到价值要几步？阻力在哪？ |
| 留存 | 用户为什么会回来？有什么习惯或网络效应？ |
| 变现 | 怎么定价、怎么分层、谁付费？ |
| 扩张 | 怎么从一个人到一个团队，从一个场景到更多场景？ |

每条热点只选一个最站得住的环节，不硬套全部。

## 事实与推断分开

- 热点本身的事实：写来源，标看到的时间。还在变化的，写「截至 某时」。
- 增长视角多半是**我们的推断**，必须标明，并写前提。
- 不替公司编数据、内部动机或结果。热点里没有的数字，写「未披露」。
- 能找到 ① 证据卡里相关的一线做法做对照时，用证据卡；找不到就不硬拉。

## 用在哪

| 用途 | 交给谁 | 要求 |
|---|---|---|
| 当日主槽位 | ② 选题 → ④ 写作 | 过门槛、大纲先批；不为赶热点跳过核验，材料不够就不发 |
| 互动回复 | ⑦ 发布互动 | 回复类型仍限补证据、解释机制、提具体问题；计入每日回复草稿上限 |
| 附加短帖 | ⑦ | 单独审批，不占用主槽位的核验时间 |

热点不改变周配比的性质：热点内容按其类型（拆解 / 清单流程 / 方法总结）计入配比。

## 输出

每天的热点候选写进 [../templates/daily-hotspots.md](../templates/daily-hotspots.md)，交作者选。作者选中、否掉的热点和理由记进取舍库「一、选题取舍」。

## 禁区

- 不蹭与增长无关的热点，不制造争议或假想敌。
- 不为赶时效改事实、夸大、写「刚刚」「突发」。
- 不预测热点带来的曝光或涨粉。
- 不引用未经验证的「追热点能获得算法加权」之类的说法。
