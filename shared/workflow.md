# 套件流程与审批闸门

8 个入口可以单独用，但共用同一套来源表、证据编号、版本记录和取舍库。下面是完整串联时的顺序。

```
① 播客拆解 → ② 增长选题与大纲 → 【作者确认大纲】
   → ④ 长文写作（中途调用 ③ 标题）→ ⑤ 去 AI 味 → 【作者审定正文和标题】
   → ⑥ 头图配图 → ⑦ 完整预览与逐条授权 → ⑧ 数据复盘 → 回流 ② ③
```

## 定位

- 素材以英文产品增长类播客为主（具体栏目由作者自选），延展成中文产品增长干货。
- 核心是获客、激活、留存、变现、扩张的具体动作、机制、证据和适用条件。
- 不追热点，不做播客摘要翻译。传播角度只服务表达，不决定选题。
- 作者的规则决定流程。外部项目只补充方法，不作为整套结构，也不作为默认运行依赖。

## 审批闸门

| 闸门 | 位置 | 未通过时 |
|---|---|---|
| 大纲确认 | ② 之后 | 不写全文、不整集翻译、不做图 |
| 正文与标题审定 | ⑤ 之后 | 不做图、不进预览 |
| 逐条发布授权 | ⑦ 预览之后 | 不发布、不进草稿箱、不互动 |
| 版本变化 | 任意阶段 | 已获批版本被改动后，重新走对应闸门 |

每次通过闸门，在 [templates/approval-log.md](templates/approval-log.md) 记一行：日期、对象、版本、谁批准、批准范围。

## 全套件禁区

- 不编造数据、引语、亲历、测试、来源或算法结论。不知道就写「待补充」。
- 不改事实，不夸大范围或因果。
- 不预测点击率、曝光或「爆款概率」。
- 不自动发布，不自动互动（点赞、评论、私信、转发）。
- 不取 Cookie，不绕过登录、拒绝或失败，不使用付费数据服务，除非作者另行明确授权。
- 已锁定的标题逐字不改。

## 共用文件

- [templates/source-register.md](templates/source-register.md)：来源表
- [templates/evidence-card.md](templates/evidence-card.md)：证据卡
- [templates/approval-log.md](templates/approval-log.md)：版本与审批记录
- [templates/decision-library.md](templates/decision-library.md)：取舍库（选中/否掉的选题、标题、改稿及原因）

## 单独安装某个入口时

把 `shared/` 一并复制到同级目录。没有 `shared/` 时，入口仍按各自 SKILL.md 中的「最低要求」执行，并在输出里注明「未读取共用来源表/取舍库」。
